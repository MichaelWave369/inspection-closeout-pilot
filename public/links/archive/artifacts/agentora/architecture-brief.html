Coordinate a team without surrendering the right to inspect, pause, deny, or repair.

Agentora v1.0.0 is a local Computational Collaborator operating studio for chat, team orchestration, memory-aware execution, approval-gated actions, workflows, and Operator Mode. Its source repository retains the established product term “agent”; this public Archive uses Computational Collaborator for the participating systems while preserving the Agentora name and source terminology.

Core boundary: coordination is not authority, role assignment is not proof of independent judgment, retrieved memory is not truth, and a heuristic mission score is not an objective verdict.
Human intent → bounded context pack → team plan and handoffs → proposed actions → approval and policy gate → operator control → outcome review → optional memory writeback

Implemented v1.0.0 core

Local runtime

Streamlit provides the primary operator interface; FastAPI provides orchestration and runtime APIs; SQLModel and SQLite store local state by default.

Memory-aware execution

Retrieval, contexts, lineage, duplicate and conflict visibility, and maintenance surfaces help the operator inspect what context entered a run.

Team orchestration

Plans, subgoals, handoffs, collaboration traces, and team views expose how work was divided and transferred.

Safe actions

Desktop and browser actions are approval-gated and constrained by path, domain, application, policy, and allowlist guardrails.

Workflow and Operator Mode

Runs can be started, paused, resumed, advanced, retried, skipped, replayed, and reviewed through visible histories.

Optional worker assist

A configured worker can receive bounded jobs; when unavailable, Agentora may fall back locally only where policy allows.

Mission integration lineage

Agentora includes optional bridges to PhiOS and AgentCeption. PhiOS owns identity, persona, memory-context packets, and writeback; Agentora owns the operator workflow and observability surface; AgentCeption owns software-execution dispatch, job, worktree, and pull-request paths. Mock mode allows the mission flow to be demonstrated without either external service.

The evolved mission loop supports context preparation, launch, operator-triggered refresh, normalized outcome review, manual writeback, optional background watching, conservative debounced auto-writeback, mission compare, export/import, retention controls, heuristic insights, optional alerts, and optional HTTP-backed MCP operations. These advanced surfaces are environment-gated; manual operator control remains the primary posture.

Stable and experimental separation

The repository identifies the core run lifecycle, memory inspection, team planning and handoffs, action approvals, workflow replay, and Operator Mode APIs as stable in v1.0.0. Cosmos, Open Cosmos, Garden, and World Garden remain optional and explicitly labeled experimental rather than required for the core general-availability path.

Memory and score truthfulness

Memory context may be incomplete, stale, duplicated, conflicting, misattributed, or irrelevant. Agentora surfaces lineage and maintenance information so the operator can inspect and correct it. Mission score, confidence, readiness, and risk fields are heuristic operator aids derived from observable mission artifacts and transitions; they are not objective truth, certification, or authority.

Upstream contracts and downstream receipts

Vibe can provide structured human intent, constraints, proof surfaces, and change boundaries. SOSA can separate observation, mapping, dissent, authorization, operation, and repair. AlphaLedgerOmega can preserve plans, approvals, action history, exceptions, outcomes, and writeback decisions. Agentora is the operating studio where those contracts become inspectable human-controlled workflows.
