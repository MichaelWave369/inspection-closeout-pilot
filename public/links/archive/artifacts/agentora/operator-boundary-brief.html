WHAT THE STUDIO MAY COORDINATE · WHAT IT MAY NOT ASSUME

A visible team is only trustworthy when its limits remain visible too.

Agentora’s operator surface is designed to show plans, context, handoffs, proposed actions, approvals, histories, and outcomes. Those records help a person govern work; they do not turn a workflow into an independent authority.

Operator authority

The operator may start a workflow, pause or resume it, advance a step, retry a recoverable failure, skip a step, approve or deny an action, inspect history, replay prior runs, correct context, request repair, and decline memory writeback. A completion recommendation cannot remove those controls.

Approval policy

The verified Operator Mode documentation states that action approval defaults to ask_once and that path, domain, and application guardrails are enforced. An approval applies only to its declared scope. It is not blanket consent for later actions, new targets, broader data access, hidden side effects, or changed intent.

Memory boundary

Retrieved context

May be useful, but may also be stale, partial, duplicated, conflicting, misattributed, or outside the current task.

Lineage

Shows where context came from and how it moved; lineage does not prove the underlying statement is true.

Writeback

Should remain reviewable and manual by default. A concise summary must not silently replace the richer evidence or dissent that produced it.

Deletion and repair

Operators need a visible path to correct, supersede, quarantine, or remove inappropriate memory under the governing retention policy.

Team and independence boundary

Different role names, subgoals, or response panels do not prove independent cognition or heterogeneous evidence. Collaborators may share the same model family, training data, context packet, orchestrator assumptions, or failure modes. Consensus may reflect correlated bias. Dissent should remain inspectable and should not be collapsed merely because a majority agrees.

Heuristic scores

Mission score, confidence, readiness, risk, compare severity, and cohort insights are triage aids. They summarize selected artifacts and state transitions using configured rules. They are not objective truth, a safety rating, a performance guarantee, a legal conclusion, a security assessment, or authority to proceed.

Optional automation

  • Worker assistance, mission watching, auto-writeback, MCP exposure, alerts, retention compaction, and calibration thresholds are environment-gated.
  • Background automation must not hide the current stage, duplicate writebacks, broaden allowed tools, or create a silent path around operator approval.
  • Worker unavailability may fall back to local execution only where the declared policy permits; it must not silently change privacy, capability, or resource assumptions.
  • Webhook alerts, external services, and worker URLs create new data and network boundaries that require separate configuration and review.

Public Mission Control Workbench

Fixed synthetic mission → inspect roles and context → review proposals → select a bounded operator response → generate a non-canonical receipt preview

The Archive workbench does not use Streamlit, FastAPI, SQLite, Ollama, PhiOS, AgentCeption, a worker node, MCP, webhooks, browser automation, desktop automation, file access, repository access, or background processes. It cannot launch, pause, approve, deny, write back, or replay a real Agentora run.

Boundary: a displayed approval, denial, pause, retry, skip, or writeback choice in the public workbench is a teaching fixture only. It is unsigned, non-persistent, non-canonical, disconnected from Agentora, and unable to affect any real person, file, account, browser, repository, service, worker, memory store, or workflow.
