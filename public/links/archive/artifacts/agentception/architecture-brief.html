SOFTWARE EXECUTION · ISOLATED WORKTREES · REVIEWABLE DELIVERY

Let the worker perform bounded software work without confusing output with acceptance.

AgentCeption is the software-execution role in the PhiOS–Agentora mission lineage. Agentora prepares and observes the operator workflow; PhiOS supplies bounded context and receives proposed writeback; AgentCeption receives an execution contract and returns job status, phase, branch, pull-request, issue, and artifact information.

Evidence boundary: a branch, patch, test result, artifact, or pull request records work performed. None of those objects proves correctness, grants merge authority, authorizes deployment, or verifies the intended real-world outcome.
Mission contract → preflight → isolated worktree and branch → bounded implementation → checks and receipts → delivery packet → pull-request candidate → human review

Current public source basis

No accessible standalone public AgentCeption repository is currently claimed by this package. The public architecture is grounded in Agentora v1.0.0 integration documentation, which assigns AgentCeption responsibility for software execution through dispatch, job, worktree, branch, pull-request, issue, and artifact paths.

Agentora’s documentation also states that the integration endpoints are intentionally thin, defensively normalized, and may require alignment with final AgentCeption schemas. This Archive record therefore describes a governed execution architecture and teaching workbench—not a verified reference implementation.

Execution contract

Repository and base

Repository identity, base branch or commit, cleanliness assumptions, allowed file paths, and expected branch naming.

Intent and acceptance

Requested outcome, bounded acceptance checks, prohibited behavior, unresolved assumptions, and the evidence required for review.

Capabilities and resources

Allowed commands, network posture, dependency policy, secret access, time and compute limits, and external-service boundaries.

Authority and stop conditions

Who may dispatch, what requires escalation, when execution must stop, and who may review, merge, deploy, or close the work.

Isolation model

A worktree or equivalent isolated workspace separates the proposed change from the canonical branch. The job should preserve the base commit, branch identity, commands attempted, changed files, produced artifacts, checks run, failures, warnings, and final diff. Isolation reduces accidental interference; it does not prove the implementation is safe or correct.

Verification and delivery packet

Checks may include tests, linting, formatting, type checks, builds, policy checks, dependency review, secret scanning, and diff review. The delivery packet should state which checks ran, which did not run, exact outcomes, known limitations, unresolved issues, scope deviations, changed assumptions, and whether a pull-request candidate was prepared.

Human review and later gates

A pull request is a review object. Repository policy, protected branches, required checks, reviewer authority, dissent, stale-base detection, conflict resolution, and explicit merge approval remain outside the execution worker’s automatic authority. Deployment is another separate event, and successful deployment still does not prove the intended user or operational outcome.

Failure as evidence

A blocked dispatch, failed test, cancelled job, timeout, conflict, rejected patch, closed pull request, or rollback remains a valid receipt. The system must not erase failed attempts to create an artificial success history. Repair may create a new candidate linked to the previous failure rather than rewriting it.

Claim boundary: this package demonstrates public architecture, Agentora integration lineage, and fixed synthetic delivery decisions. It does not establish a public AgentCeption implementation, secure sandboxing, correct repository isolation, reliable code generation, successful testing, secret protection, supply-chain safety, vulnerability absence, mergeability, deployability, production suitability, organizational permission, or any completed software outcome.
