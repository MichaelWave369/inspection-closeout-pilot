PARALLAX ARCHIVE CORE

Unified System Architecture and Build Roadmap

Master Design Specification — Version 0.1

Prepared for Mikey / Parallax • July 24, 2026

Executive Summary

The Parallax Archive Core is the shared content, routing, state, and provenance system beneath every terminal edition. It prevents the gallery from becoming separate products and ensures that each project is authored, reviewed, and published once before being translated into a machine-specific presentation.

North-Star Experience

A visitor may discover the archive through the IBM 5100, remember its origin through the SL1200, enter its mature future through PAT Mk.1, play through Breadbox 64, browse exhibitions through Gallery 128, or inspect practical systems through the Field Luggable. Regardless of entry point, the same project has the same title, status, artifacts, claims, relationships, and public URL.

Core Decision

A graph is a presentation. The Archive Core is the canonical domain beneath it. Shells may change the metaphor—tape, file, node, program, exhibition piece, or field package—but never the project truth.

Recommended Build Sequence

Freeze the archive schema. Define project, artifact, relationship, shell, route, and publication contracts.

Prepare a curated launch set with clean assets and concise summaries.

Build the shell-neutral routes, manifests, viewers, search, validation, and publication pipeline before increasing shell fidelity.

Product Constitution

Archive above shell. The body of work remains reachable even if a specific immersive shell fails or is disabled.

One source of truth. Every public fact originates in a canonical manifest or ledger receipt.

Direct links are first-class. Every project and artifact has a stable URL outside the simulated machine scene.

Goals

Publish a coherent, memorable portfolio experience rather than a normal project grid.

Allow one project record to appear natively in every terminal edition.

Make every project directly shareable and understandable outside the shell scene.

Non-Goals

The first release is not a general-purpose content management system.

The first release does not require full processor emulation or authentic legacy operating-system execution.

The public gallery is not a social network, marketplace, or unrestricted file-upload service.

Unified Architecture

The public experience is a content platform with multiple immersive clients. Visitors, search engines, direct links, shell scenes, curator workflows, and future physical hardware all depend on the same archive domain.

Dependency Rule

Shells may depend on Archive Core. Archive Core must never depend on a shell. This keeps project identity portable and prevents presentation code from becoming the source of truth.

Progressive Delivery

Accessible HTML and project metadata load first. Client runtime then hydrates search, shell transitions, viewers, and visitor preferences. High-fidelity effects load only after the core route is usable.
