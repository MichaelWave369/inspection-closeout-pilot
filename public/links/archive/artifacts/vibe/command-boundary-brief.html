COMMAND ATLAS · AUTHORITY · SIDE-EFFECT BOUNDARY

The command that can change a file must be treated differently from the command that only explains it.

Vibe’s public command surface ranges from read-only inspection and verification through artifact generation, local registry operations, scaffold creation, and a narrow set of optional patch-apply flows. Safe use requires those classes to remain visibly distinct.

Read and verify class

Verification

verify, verify-proof, inspect-proof, diff, merge-verify, semver, negotiate, ci-check, self-check, and brief-generation commands inspect or derive bounded results.

Discovery

search, registry-inspect, compat, domains, standard-library listing, template listing, snippet listing, receipt inspection, and project inspection expose local state.

Artifact-writing class

Commands such as snapshot-put, verify-proof, package build, local publish, scaffold generation, exported reports, test manifests, bundles, and emitted targets can write new local artifacts. Their output must remain traceable to the source, configured backend, assumptions, and gate result.

Code-modification class

PhiPython patch and starter-test flows may offer --preview and --apply. These are bounded candidate changes—not a correctness proof. Preview should be the default review posture; apply requires explicit human selection and must preserve local repair receipts. Multi-file plans remain narrow and preview-first.

Explain / inspect → low side effect  ·  Write artifact → declared path  ·  Modify code → explicit preview, selection, apply, receipt

Safe-mode policy

  • No hidden apply, no silent overwrite, no remote code loading, and no automatic patching merely because a candidate is ranked highly.
  • No claim that heuristic explanation, traceback parsing, starter doctor checks, generated tests, or candidate fixes establish runtime correctness.
  • No promotion of a local review artifact, repair receipt, or bundle into a formal correctness proof.
  • No interface layer—including SIGLStudio—may bypass Vibe’s canonical verification and proof surfaces by implementing a weaker duplicate gate.

Bounded natural-language bridge

Vibe’s interchange-from-text and scaffold helpers create deterministic structured starting artifacts from bounded text inputs. They are not universal natural-language understanding, autonomous requirements engineering, or permission to infer unstated authority, side effects, data rights, safety conditions, or acceptance criteria.

Public workbench boundary

The Archive workbench uses fixed synthetic examples only. It does not parse arbitrary visitor code, execute Python, compile a real target, upload files, write snapshots, apply patches, access the Vibe registry, call a model, or produce a canonical Vibe proof artifact.

Boundary: Command availability is not command authorization. A passing preservation report does not grant permission to deploy, modify another person’s code, access data, affect money, contact users, or take any external action. Those authorities must be separately declared and governed.
