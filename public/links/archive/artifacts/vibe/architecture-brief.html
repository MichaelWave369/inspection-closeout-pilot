INTENT-FIRST LANGUAGE · LOCAL-FIRST COMPILER

Make intent the source code—and make preservation the condition for emission.

Vibe is a local-first language and compiler toolchain built around .vibe specifications. The implemented compiler accepts an emission only when its current verification pipeline reports that the generated artifact preserves the declared intent above the configured bridge threshold.

Core law: intention is source code. Preservation is compilation truth. When required preservation checks fail, emission is blocked.
Intent specification → parse → typed IR → verification obligations → backend evaluation → preservation outcome → proof/report → emit or block

The source object

A Vibe specification can declare a goal, typed inputs and outputs, preserve conditions, constraints, bridge settings, domain metadata, and an emit target. The canonical payment-router example declares a goal of choosing the cheapest valid processor while preserving latency, failure-rate, compliance, readability, testability, deterministic selection, secret safety, and graceful fallback.

Implemented compiler spine

Parse and lower

The source is parsed into an abstract syntax tree and lowered into typed intermediate representation.

Generate obligations

Preserve, constraint, bridge, and domain declarations become machine-checkable obligation surfaces.

Verify and report

Configured backends evaluate obligations and produce preservation outcomes, diagnostics, summaries, hashes, and optional proof artifacts.

Gate emission

The target artifact is emitted only when the implemented gate passes. Failed obligations retain a report and require repair.

Current implemented range

The public repository documents parser and typed-IR foundations, verification surfaces, backend abstraction, deterministic emit targets, calibration and proof artifacts, package lifecycle foundations, a local registry, a stdio language server, CI bridge checks, bounded cross-domain profiles, self-checking, semantic intent diff and versioning, intent negotiation, machine-consumable briefs, and initial standard-library intent contracts.

PhiPython is a bounded guided Python layer inside Vibe. It can scaffold starter projects, explain common constructs, translate common errors, generate bounded candidate fixes, preview narrow patches, create starter-oriented tests, and export local review artifacts. Vibe remains the intent source of truth.

What “proof” means here

In current Vibe, proof means machine-checkable metadata produced by the implemented verifier and proof pipeline: obligation outcomes, hashes, backend metadata, summaries, evidence surfaces, and a preservation-gate result. It does not mean complete theorem proving or full formal verification of arbitrary program semantics.

Local-first provenance

Snapshot storage, package registry operations, reports, proof artifacts, repair receipts, and review bundles are local-first. Snapshot proof artifacts preserve the input mode and content identity rather than inventing a filesystem source path. External obligation providers use a controlled registration seam; they are not remotely loaded or automatically discovered.

Upstream role

Vibe is the canonical intent and proof engine upstream of SIGLStudio and later code-generation experiences. Those interfaces should consume Vibe’s proof surfaces rather than duplicate or weaken the preservation logic.

Claim boundary: Vibe is a working prototype compiler with implemented bounded language and domain slices. It is not complete language coverage, universal intent understanding, full verification of arbitrary software, guaranteed correctness, automatic legal or safety approval, or evidence that every generated artifact preserves every unstated human expectation.
